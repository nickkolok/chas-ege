# Рекомендации и соглашения по работе с `git`

Это - НЕ инструкция для начинающих.
Здесь приводятся рекомендации, соглашения и нетривиальные советы
для тех, кто уже более-менее понимает, как работать с `git`.


## Основная ветка - `devel`

И да, мы отказались от `master` до того, как это стало `main`стримом.


## Удалённые репозитории

Не от слова "удалить", а от слова "далеко".

Предполагается, что основной репозиторий проекта называется `origin`,
а остальные форки контрибьюторов - по их никам, т.е. как-то так:

```
$ git remote -v
origin  git@github.com:nickkolok/chas-ege.git (fetch)
origin  git@github.com:nickkolok/chas-ege.git (push)
kalendar2       git@github.com:Kalendar2/chas-ege.git (fetch)
kalendar2       git@github.com:Kalendar2/chas-ege.git (push)
sugarhedgehog   git@github.com:SugarHedgehog/chas-ege.git (fetch)
sugarhedgehog   git@github.com:SugarHedgehog/chas-ege.git (push)
veronikakit     git@github.com:VeronikaKit/chas-ege.git (fetch)
veronikakit     git@github.com:VeronikaKit/chas-ege.git (push)
zer00player     git@github.com:Zer00Player/chas-ege.git (fetch)
zer00player     git@github.com:Zer00Player/chas-ege.git (push)
```

(и, возможно, ещё что-нибудь).


## Начало доработки чужого пуллреквеста

Забираем ветку из PR 12345678 локально:

```
git fetch origin pull/12345678/head:pr-12345678
git checkout pr-12345678
```


## Работа над новой фичей

```
git fetch origin
git checkout origin/devel
git checkout -b имя_ветки
```

А в конце, понятно, `git push`.


## Добавление нового шаблона

Одним коммитом добавляется сам файл нового шаблона,
соответствующая строка в `main.js` и в `fipi.js`
(если `fipi.js` есть в соотв. папке и задача соответствует ФИПИ).
Если нужной категории нет, этим же коммитом создаётся `main.js`
с единственным номером:
```js
window.nomer=[
	1234567890,
].iz();
```
где `1234567890` - номер добавляемого шаблона.

Как правило, соответствующая ветка называется `newtask-1234567890`.


## Принцип атомарности

Каждое замечание по пуллреквесту,
а также самостоятельно найденная проблема,
исправляется отдельным коммитом с осмысленным названием.

Исправление code style всегда идёт отдельным коммитом.

Исправление орфографии и пунктуации всегда идёт отдельным коммитом.


## Команды, которых лучше избегать

### `git rebase`

Как правило, при доработке пуллреквестов использовать его - плохая идея,
если только в пуллреквесте или задании не сказано явно,
что нужно отребейзить.
Неуместный `git rebase` ломает историю обсуждения пуллреквеста.
Однако, `git rebase` может быть изредка полезен локально, если не сделан `git push`
(или хотя бы не открыт пуллреквест).


### `git push --force` / `git push --force-with-lease`

Про существование этой команды, честно говоря, вообще лучше не знать.
И не использовать её, если этого не требуется явно.


### `git add .` и `git add -A`

Может случайно включить в коммит что-нибудь, что лежало в репозитории без дела,
но и без вписания в `.gitignore`.
Лучше всегда указывать, какие конкретно файлы надо `git add`.


### `git pull`

Это команда хороша тем, что делает одновременно `fetch` и `merge`,
и ровно этим же плоха.
В проекте не принято иметь большие ветки,
в которые надо было бы часто приливать внешние изменения.
