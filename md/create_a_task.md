# Создаём новый шаблон

## Общие принципы

### DRY - Don't Repeat Yourself

Если нужна какая-то функция, которая кажется стандартной -
скорее всего, где-то в библиотеке она уже есть готовая.
Нужно просто поискать.

Искать нужно и в подключённом mathjs (в шаблонах он доступен как `math`):
своя реализация того, что там уже есть (`math.lcm`, `math.norm`, `math.dot` и т.п.), — тоже дубль.
Допустима тонкая обёртка в стиле проекта (метод `Number.prototype` или `Array.prototype` поверх `math`);
`math` в ней берётся в момент вызова, потому что `chas-lib.js` загружается раньше mathjs.
Дубль допустим, если он заметно быстрее, безопаснее или учитывает случаи, специфичные для проекта;
причину стоит записать комментарием рядом с реализацией.

### Принцип обобщения

Смысл шаблона не в том, что он в сжатом виде хранит задачи-образцы,
а в том, что он обобщает задачи-образцы,
позволяя получать сотни и тысячи аналогичных задач.

Как правило, обобщение предпочтительнее перечисления.
Например, если нам нужно чётное положительное число,
не превосходящее 10 и при этом не являющееся полным квадратом,
не надо писать:
```js
let n = [2, 6, 8, 10].iz();
```
Лучше написать:
```js
let n = slKrome(isPolnKvadr, 2, 10, 2);
```
*Потому что однажды потребуется расширить диапазон до 20...*


## Определяем номер

Имя шаблона - это всегда целое число в десятичной системе счисления.
Как правило, в проекте используются номера из СдамГИА (бывшего РешуЕГЭ),
а также Открытого банка заданий (Обзад).

## `set*Task({...})`

Это функции, отвечающие за собственно создание задания.

## Модификаторы

Это функции, которые изменяют или дополняют текст задания и решение после создания.

Все `set*Task({...})` и модификаторы определяются в `src/chas2/task.js`.

`chas2.task` и `NAtask` - это одно и то же.
Нельзя только смешивать их в одном шаблоне!


## `genAssert` и `retryWhileError`

Случайные данные подходят не всегда, поэтому тело шаблона обычно оборачивают
в `retryWhileError` (`lib/func_assert.js`):

```javascript
retryWhileError(function() {
	let a = sl(2, 9);
	genAssert(a % 3 != 0, 'a кратно 3'); // неподходящие данные — бросить исключение
	// ...
}, 10000); // сколько раз пробовать; по умолчанию 1024 * 1024
```

`retryWhileError` вызывает функцию снова, пока она не отработает без исключения,
но не больше заданного числа раз.

Важно: повторяется **любое** исключение, а не только брошенное `genAssert`.
Опечатка в имени, `TypeError`, явная ошибка в настройках `set*Task({...})`
(например, неподдерживаемое значение параметра) тоже просто повторяются,
и шаблон падает только после того, как попытки кончились, с сообщением
`Could get nothing but errors (iterations: N)`. В нём есть первые 16 ошибок и
статистика «Detailed stats»: сообщение — сколько раз встретилось.
Ошибка в коде или настройках видна там как сообщение, которое встретилось во всех
N попытках. Чтобы увидеть её сразу, тело шаблона можно один раз вызвать без
`retryWhileError`.

Если шаблон отбраковывает большинство наборов данных, он иногда не укладывается
в лимит попыток и задачу не выдаёт. Это ловится массовым прогоном
(см. [ревью пуллреквеста](how_to_review_PR.md)); лимит тогда увеличивают
(у тяжёлых шаблонов он доходит до 200000) или ослабляют ограничения.

## Механизм предпочтений (`preference`).

Мы используем `preference` в случае, когда один шаблон может генерировать несколько родственных типов задач.
Например, задачи вида
"Дана сторона квадрата, найдите его площадь"
и
"Дана сторона квадрата, найдите его периметр"
могут быть отнесены к одному шаблону,
но тогда необходимо предусмотреть `preference`,
позволяющий генератору принудительно переключать шаблон на один из вопросов.
Если `preference` не задан извне, шаблон использует случайный выбор.

Для получения `preference` используется функция `getSelectedPreferenceFromList(key, preference)`.
Использование `getListedPreference()` считается устаревшим и категорически не рекомендуется.
Весь массив `preference` необходимо передавать в `setTask({})` (см. файлы-примеры, указанные ниже).

`preference` в `setTask({})` — это **массив массивов**:
по одному массиву на каждый вызов `getSelectedPreferenceFromList(key, …)`, в том же порядке.
Даже если список единственный, его нужно оборачивать: `preference: [preference]`.
Для двух независимых списков — `preference: [preference1, preference2]`.

Плоский массив строк для единственного списка генератор тоже поймёт
(`generateVariations` в `lib/func.js` оборачивает одномерный массив),
и генерация будет идентичной. Но оборачиваем для единообразия:
если в шаблон добавят второй список, плоская склейка молча сломает перебор
(комбинации станут одноэлементными, а непокрытый список уйдёт в случайный выбор).
Смешивать плоскую и вложенную формы нельзя.

Пример из ЕГЭ [про перевод температур](../zdn/matege2024b/4/509729.js) :
```javascript
let key = '509729';
let preference = ['CelToFar', 'FarToCel']; // Из Цельсия в Фаренгейт или наоборот
let rand = getSelectedPreferenceFromList(key, preference);

let degreeName = ['Цельсия', 'Фаренгейта'][rand];
// ...
NAtask.setTask({
	// ...
	preference: [preference], // массив массивов, даже если список один
});
```

Пример из ОГЭ [про числовые прямые](../zdn/matoge2024/7/311392.js) :

```javascript
let key = '311392';
let preference = ['hideNumbers', 'showNumbers']; // Скрывать числа на засечках или показывать
let rand = getSelectedPreferenceFromList(key, preference);
```

Примеры работы с двумя независимыми `preference`:
`zdn/matege2024b/15/506736.js`, `zdn/matege2024b/4/513771.js`, `zdn/matege2022p/9/509192.js`.

### Формулировки ФИПИ — через `preference`

Шаблон по прототипу ФИПИ должен уметь выдать **каждую формулировку**, которая встречается
у заданий этого прототипа в банке (все задания прототипа — его группа в `dups.d` fipi-watch,
см. `dev/chas-ege.md` там). Каждая формулировка — отдельное значение `preference`, а не случайный
выбор внутри шаблона: так генератор может запросить любую.

- **Небрежные формулировки ФИПИ тоже нужны.** Например, «Площадь прямоугольного треугольника 210.
  Один из катетов 21. Найдите гипотенузу» — без «равна» и «равен», как у шести заданий из десяти;
  «В треугольнике каждая из двух сторон равна 5, а третья сторона равна 8. Найдите длину медианы,
  проведённой к третьей стороне» — без букв и без чертежа, хотя у остальных заданий прототипа
  буквы и чертёж есть. Значение `preference` для такой формулировки отключает и то, чего в ней нет
  (буквы, чертёж).
- **Откровенно неверные не нужны**: опечатка, меняющая смысл, противоречивые данные, ошибка
  в вопросе. Такое задание указать в комментарии шаблона по ID и написать, почему его формулировки нет.
- Второй список формулировок — второй вызов `getSelectedPreferenceFromList` и
  `preference: [preference1, preference2]`. Если формулировка имеет смысл только при одном
  значении первого списка, второе значение второго списка стоит наполнить и для остальных
  (другой вариант ФИПИ для другого вопроса), иначе комбинации выйдут одинаковыми.
