# Делаем *пачку команд* для вставки в консоль

Эта часть руководства может потребоваться только в экзотическом случае:
для тех, кто команды `git` / `gh` знает в совершенстве,
но при этом не имеет доступа к консоли и/или аккаунту на GitHub.
Естественный вариант только один: всякие агенты и ассистенты.

В качестве терминала предполагается `bash`.

*Пачка команд* начинается с настройки терминала,
чтобы он не обрабатывал табуляцию и восклицательные знаки:

```bash
set +H
bind 'set disable-completion on'
bind 'set enable-bracketed-paste on'

bash -e <<'BUNCH_DONE'
```
Последняя строка открывает субтерминал через heredoc,
чтобы пачка команд при ошибке завершилась,
а не продолжала бесконтрольно исполняться,
и для изоляции в целом.

Далее производится переключение на нужную ветку
(не забываем про `git fetch` перед переключением, если он нужен),
вносятся исправления в файлы,
создаётся последовательность коммитов и т.д.
Можно использовать:
`cat`, `sed`, `echo`, `tee`, `printf`, `awk`, `sort`, `jq`,
`node`- и `python`-скрипты,
а также любые команды `git` и `gh`.

В конце, если поручение это предполагает,
можно открыть Pull Request с помощью `gh`.

Основной способ создать новый файл
(или полностью переписать существующий):
```bash
cat > path/to/file <<'EOF'
noindent
	indent
noindent
EOF
```

При изменении файла необходимо учитывать, как там проставлены отступы: пробелами или табами,
и не изменять, а также не смешивать типы отступов.

Полезно после создания или изменения файла `*.js`
перед `git add` вызвать для проверки синтаксиса
```bash
node --check path/to/file.js
```

В конце нужно выйти из субтерминала:
```bash
BUNCH_DONE
```

Наконец, хорошим тоном считается вернуть терминал в исходное состояние:
```bash
bind 'set enable-bracketed-paste off'
bind 'set disable-completion off'
set -H
```

Команду `git push ...` следует приводить отдельно от пачки,
поскольку человек, который будет запускать пачку,
может иметь закономерное желание сначала изучить её результат.
Тем не менее, команду `git push ...` после пачки приводить необходимо,
аккуратно сверив название репозитория и ветку.

Когда кажется, что пачка уже готова,
следует ещё раз перепроверить:

- Имена всех затронутых файлов

- Имена всех затронутых репозиториев и веток
