# Облачная песочница Claude Code: ограничения и приёмы

Для ассистента, который работает в облачной сессии Claude Code (claude.ai/code):
контейнер Linux, клон форка, сеть через прокси. Здесь сборка и тесты идут
полноценно; если песочница урезанная (нет `npm install`, короткий бюджет вызова) —
читать [Отладку шаблона в песочнице с ограничениями](sandbox_template_debug.md).

Сначала — «С нуля» и «GitHub: что доступно»: остальное нужно не всегда.
Ниже — то, что проверено в сессии ноября 2026 года; настройки окружения
меняются, поэтому неожиданный отказ стоит перепроверить одной командой.

## С нуля: пять команд

В песочнице клонирован **свой форк** (`origin`), основного репозитория среди
remote нет, пакеты не стоят:

```bash
git remote add upstream https://github.com/nickkolok/chas-ege
git fetch upstream devel md-qwen-repo-structure '+refs/pull/*/head:refs/remotes/upstream/pr/*'
npm install
npm install --no-save grunt-cli canvas   # одной командой, см. how_to_review_PR.md, «Подводные камни»
./node_modules/.bin/grunt                 # около 100 с; npm test — ещё около минуты
```

- `git fetch` публичного репозитория работает без авторизации, головы всех PR —
  за секунды (`upstream/pr/N`).
- Ядер обычно 4 (`nproc`): сборки и прогоны параллельно — не больше чем в 4 потока.
- Контейнер эфемерный: всё нужное — коммитить и пушить; черновики и большие JSON
  прогонов — во временный каталог сессии, не в репозиторий.

## GitHub: что доступно

| Что | Как | Работает? |
|---|---|---|
| Ветки, головы PR, файлы | `git fetch`, `git show` | да |
| Сырые файлы и патч PR | `curl https://raw.githubusercontent.com/…`, `curl https://patch-diff.githubusercontent.com/raw/nickkolok/chas-ege/pull/N.patch` | да |
| Состояние, автор, заголовок, **описание** PR | `gh api -X GET search/issues` (ниже) | да |
| REST `repos/nickkolok/chas-ege/…` (PR, база, ветка, **комментарии**, CI) | `gh api` / `curl api.github.com` | **нет**: 403 «GitHub access to this repository is not enabled for this session» |
| REST по своему форку | `gh api repos/<свой ник>/chas-ege/…` | да |
| GraphQL | `gh api graphql` | **нет**, ни для какого репозитория |
| Страница PR на github.com | `curl` | **нет** (403); через WebFetch — да, но см. ниже |
| Git LFS своего форка fipi-watch | `git lfs pull --include=…` | да |

REST к основному репозиторию закрыт не сетью, а настройкой сессии: репозиторий
не подключён к ней с правами. Подключить его может пользователь (GitHub App
на репозитории, репозиторий в настройках окружения); тогда REST, а с ним
и комментарии, становятся доступны. Запрос ассистента (`add_repo` с
`access: "push"`) в авто-режиме может быть отклонён правилами разрешений
сессии — так было 26.11.2026; это решает пользователь, обходить не надо.

### Описание и состояние PR — поиском

Одна выдача на всю пачку, `body` — полное описание PR:

```bash
gh api -X GET search/issues --paginate -f per_page=100 \
	-f q='repo:nickkolok/chas-ege is:pr created:>=2026-11-01' > /tmp/prs.json
```

`--paginate` склеивает страницы в один файл **подряд, без разделителя**:
`JSON.parse` на нём падает («Extra data»). Читать по объектам:

```bash
node -e '
const s = require("fs").readFileSync("/tmp/prs.json", "utf8");
const items = JSON.parse("[" + s.replace(/}\s*{"total_count"/g, "},{\"total_count\"") + "]").flatMap((p) => p.items);
for (const n of process.argv.slice(1).map(Number)) {
	const it = items.find((x) => x.number === n);
	console.log("#" + n, it.state, it.pull_request.merged_at || "-", it.user.login, it.comments + " комм.", it.title);
}' 3711 3717
```

Комментариев поиск не даёт, только их число (`comments`). Если комментариев нет —
читать нечего; если есть и REST закрыт — см. «WebFetch» ниже или попросить
подключить репозиторий.

### База PR без REST

Базу (`devel` или `md-qwen-repo-structure`) REST дал бы сразу; без него —
по содержимому. Ветка документации ушла от `devel`, поэтому дифф `devel...PR`
у PR в документацию тащит её собственные коммиты (`dev/`, `md/`) и выглядит
как PR в `devel`. Проверять от обеих баз:

```bash
N=3814
for base in devel md-qwen-repo-structure; do
	echo "$base: не md — $(git diff --name-only upstream/$base...upstream/pr/$N | grep -vc '^md/')"
done
```

Ноль хотя бы от одной базы — PR в ветку документации. Так же считает
`dev/review-batch.js` (#3812).

## Чтение страниц: curl, а не WebFetch

- **Документацию и любые сырые файлы** — `curl -sSf https://raw.githubusercontent.com/…`
  в файл и `cat`/`sed -n`. Агент WebFetch возвращает пересказ: цитаты из
  непроверенных источников у него ограничены 125 знаками, и документ целиком
  он не отдаст.
- **Страницу PR с обсуждением** (когда REST закрыт) WebFetch прочитать может,
  но это дорого: на обсуждение двух PR по 15 комментариев ушло около 135 тыс.
  токенов агента, а хвост длинной страницы вернулся пересказом, не дословно.
  Просить у агента конкретное: какие замечания были, кем, закрыты ли, что писали
  боты, — а не «перескажи страницу».

## Ревью: инструменты и время

- Пачка PR — `node dev/review-batch.js N1 N2 …` (#3812; пока он не смёржен —
  запускать из рабочей копии на голове PR: `git worktree add --detach ../rb upstream/pr/3812`,
  `ln -s "$PWD/node_modules" ../rb/`). Первый запуск на 14 сборках — около 6 мин
  в 4 потока, повторный — секунды. `--no-build --no-worktrees` — только карта пачки
  и silentpr, тоже секунды.
- Потребители — `node dev/consumers-diff.js` (#3813). Каждый шаблон — три процесса
  (эталон дважды и «после»), около секунды каждый.
- **Все шаблоны** (PR в `Gruntfile.js`, `src/` или во что-то, что меняет весь бандл):
  1255 шаблонов по 5 задач — около часа в 4 потока. Запускать первым и в фоне,
  остальное ревью — пока он идёт:

  ```bash
  git ls-files -s 'zdn/*.js' 'zdn/*.cpp' | awk '$1 != "120000" {print $4}' |
  	grep -v -e '/main\.js$' -e '/fipi\.js$' > /tmp/all.txt
  node dev/consumers-diff.js --before devel --after N --list /tmp/all.txt --iterations 5 --jobs 4
  ```

  Фон на `devel` от 25.11.2026 (`b2142b9ce`): 9 шаблонов падают и до, и после,
  у 2 (`matege2024b/8/506771`, `514397`) эталон не повторяется при одном зерне.
  Новое — всё, чего нет в этом списке.
- Кеш сборок — по дереву git: пока `devel` стоит, повторные прогоны берут сборки
  из кеша; после каждого мержа в `devel` слияния PR с ним собираются заново
  (по 100 с на PR).

## Push и silentpr

- `origin` — свой форк: туда пушатся и рабочая ветка сессии, и `silentpr/…`
  к чужим PR ([`silentpr`](silentpr.md)).
- Создать PR в основной репозиторий без подключённого репозитория нельзя
  (REST закрыт, см. выше): ветку пушат в свой форк и дают пользователю ссылку
  `https://github.com/nickkolok/chas-ege/compare/<база>...<свой ник>:<ветка>`.
- Удаление веток может быть отклонено — тогда команду удаления выводят
  пользователю одной строкой ([`silentpr`](silentpr.md), «Удаление»).

## Shell: что отклоняется

- Длинная однострочная команда с вложенными `$(…)` в цикле может быть
  остановлена проверкой безопасности оболочки, даже если ничего не удаляет
  («can't be sure it read this command the way the shell will»). Тот же код,
  записанный в файл скрипта и запущенный `bash файл.sh`, проходит.
- Так же останавливается **heredoc с программой**: `python3 - <<'EOF' … EOF` и
  `cat > правка.py <<'EOF' … EOF; python3 правка.py` со скриптом правок (кавычки, `$`, `\`
  внутри) — так было дважды 27.11.2026, хотя ничего не удалялось. Правку файла делают
  инструментом Edit (точная замена); программу записывают инструментом Write в файл
  и запускают `python3 -I файл.py` (`node файл.js`). Heredoc с обычным текстом проходит:
  сообщение коммита в `git commit -F - <<'EOF'`, короткий shell-скрипт в `cat > файл.sh`.
- Фоновые долгие команды (сборки, прогоны всех шаблонов) — с выводом в файл:
  ход работы читается из него, а не ожиданием в переднем плане.
